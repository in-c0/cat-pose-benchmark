## Runner defect discovered

The local run also exposed a Windows PowerShell 5.1 defect in the first runner implementation. When the native Unity process streams were redirected, `$LASTEXITCODE` could be empty even though Unity exited `0` and produced the export, causing:

```text
Unity S0B export failed with exit code .
```

The comparator result above was obtained by invoking the Python comparator directly after the successful Unity export.

The runner has been changed to use `Start-Process -Wait -PassThru` and the returned process object's `ExitCode`, with Unity logging to a temporary file. This removes the `$LASTEXITCODE` dependency from the Unity execution boundary.
